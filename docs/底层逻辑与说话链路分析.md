# 大肥鱼「底层逻辑 → 说话」链路分析报告

> 时间：2026-10-31 15:20
> 方法：静态追踪 `plugins/ai_group.py` 的 `build_system_prompt()` + `_compose_chat_messages()` 调用链，逐项核对每个数据源是否真的进入 LLM 请求。

---

## 一、结论先说

**大部分是通的，但有一条链路是"条件性"的，容易被误以为一直在起作用。**

| 链路 | 通？ | 说明 |
|---|---|---|
| persona（人设） | ✅ | 稳定前缀第一段，永久生效 |
| 人格内核（soul traits/rules） | ✅ **今天刚接** | 在 volatile 尾部（第④层），会进 prompt |
| 人格成长（solidified） | ✅ | 同上，volatile 尾部 |
| 激素（DA/CORT/…） | ✅ | 状态块，每轮注入 |
| 记忆召回（长期记忆） | ⚠️ **条件触发** | 只在消息命中「记忆意图」时才召回 |
| 短期记忆（当前对话） | ✅ | 走 history 多轮 |
| 念头 / 欲望 | ✅ | 影响主动私聊，不影响单轮回复内容 |
| 梦境 | ❌ 不进 prompt | 只在早上偶尔提一句（`morning_line`） |

## 二、prompt 六层结构（真实顺序）

`_compose_chat_messages()`：

```
① system(稳定前缀)   security + cfg.persona.prompt + 规则 + 活人预设 + 状态读法
② history 多轮       真实对话历史（只增不改）
③ extra_blocks       慢变块（词库/档案）+ 【回忆】+【群聊近况】
④ volatile_prompt    状态/心情/关系/性别/别复读 + 人格内核 + 成长 + 日期 + 天气
⑤ time_block         每轮必变
⑥ user               当前消息
```

### 关键发现（和昨天报告不同）

昨天我说「人格内核注入在 extra_blocks（第③层）」——**错了**。

实际代码：

```python
_extra = [soul, growth, dates, weather]
if _extra:
    volatile = volatile + "\n" + "\n".join(_extra)   # ← 拼进 volatile（第④层）
```

**soul 在第④层**。功能上没问题（照样进 prompt），但两个后果：

1. 缓存角度：第④层本来就不缓存，所以**谈不上优化也谈不上损失**
2. 优先级角度：它排在「状态/心情」之后，模型对它的注意力弱于状态块

## 三、逐条链路核对

### ✅ ① 人设（persona）

```python
static_prefix = security_prompt + cfg.persona.prompt + DESKTOP_PET_SETTING
base_stable = static_prefix + private_prompt + privacy_prompt + 规则 + living_preset + STATUS_LEGEND
```

走稳定前缀，**逐字节稳定才有缓存**。`persona.md` 本身只在 `_persona_snippet()` 里被读（用于视频场景），真人设来自配置 `cfg.persona.prompt`。

### ✅ ② 人格内核（今天新接的）

```
soul_aggregation.prompt_block()
  ↓
_extra → volatile
```

当前内容：

```
【人格内核】（这是你自己，别念出来，只当行为依据）
· 你是：嘴硬心软、贪吃偷懒、爱睡觉、记仇不持久、喵语气吐槽、爱拆梗自学、动手修插件、记账式互赞
· 你的规矩：绝不说脏话；被骂也不翻脸；半夜被艾特先抗议；遇技术问题自己修；吐槽用喵语气；不主动提钱
```

**以前这段完全不存在**，现在会进 prompt。

### ✅ ③ 人格成长（旧链路）

`_growth_snippet()` 读 `persona_growth.json` 的 `solidified` 条目，同样进 volatile。

### ✅ ④ 激素

状态块里带 `CURRENT_DAILY_MOOD` + 情绪/吃饭/时间压缩行，每轮注入。

### ⚠️ ⑤ 长期记忆召回（条件性！）

```python
mem_intent = detect_memory_intent(user_msg, is_private=True)
if mem_intent:
    mem_text = recall_memory(...)
    extra_blocks.append("【回忆】\n" + mem_text)
```

**只有消息被判定为「记忆意图」时才召回**（比如"你还记得…""上次说的…"）。

普通聊天（"在吗""吃了吗"）**不会带长期记忆**，只带 history 里最近几轮。

这意味着：
- 205 条长期记忆里，绝大多数时候**只有 3~8 条历史在起作用**
- 如果 `detect_memory_intent` 判断不准，她就会"记不住"

### ✅ ⑥ 短期记忆

`_history_messages()` 把当前会话最近 N 轮作为真实多轮消息塞进 ②。这是每轮都在起作用的。

### ✅ ⑦ 念头 / 欲望

影响的是**主动私聊**（`desire.urge()` → 是否发起对话），不影响单轮回复的措辞。

### ❌ ⑧ 梦境

`dreams.json` 不进 prompt。只在 `morning_line()` 里早上偶尔提一句。所以昨晚那个梦，**不会在今天的对话里被提起**，除非早上那次触发。

## 四、真正决定「说话像不像她」的因素（按权重）

| 权重 | 因素 | 位置 | 稳定性 |
|---|---|---|---|
| ★★★★★ | `cfg.persona.prompt`（人设正文） | ① 稳定前缀 | 不变 |
| ★★★★☆ | 当前状态（心情/激素/时间） | ④ volatile | 每轮变 |
| ★★★★ | history 最近几轮 | ② | 只增不改 |
| ★★★ | 人格内核（soul） | ④ 末尾 | 每天 |
| ★★★ | 成长条目 | ④ 末尾 | 每 2h |
| ★★ | 【回忆】长期记忆 | ③ | **条件触发** |
| ★ | 【群聊近况】 | ③ | 条件触发（提到"群"） |

---

## 五、风险与缺口

### 🔴 R1:记忆召回是"命中即用，不命中就完全没有"

`detect_memory_intent` 是个关键词/规则判断。如果它漏判，机器人就表现得"忘了"。

**建议**：对私聊主人时，**无条件追加 3~5 条语义相关记忆**（向量召回已有 `_log_vec`），成本可控（几百 token）。

### 🟠 R2:soul 在 volatile 末尾，优先级偏低

模型读 prompt 有"首尾效应"，volatile 末尾在 user 之前，其实位置不差；但和「状态/心情」混在一起时，容易被状态盖过。

**建议**：如果发现"讲了准则但没遵守"，考虑把**已固化的 3~5 条准则**提到 ① 稳定前缀（需要 trait 稳定度统计）。

### 🟠 R3:人格内核每晚才更新

今天说的"别这么冲"不会立刻生效，最多等到当晚 3:10。

**建议**：加"记住：以后 XXX"的直写口子。

### 🟡 R4:梦境基本不参与对话

昨晚生成的梦只在早上偶尔提一句，白天问"你昨晚梦到什么"她不会知道。

**建议**：`dreams.json` 最近一条加进 volatile（一天一条，成本很小）。

---

## 六、给"以后人格进化"的建议

1. **保持 soul 一天一变**（别实时重算），否则第 ④ 层每轮变，等于把 volatile 变成纯动态块
2. **固化后的准则才考虑进稳定前缀**——只在连续 N 天不变时冻结
3. **记忆召回从"条件触发"改成"私聊必定带 Top3"**——这是"她记不记得"的最大变量
4. **梦境最近一条进 volatile**——让"昨晚的梦"能自然被提起

---

## 七、一句话总结

> 人设、状态、历史、人格内核都在起作用；
> **唯一一个"看起来有、其实经常不生效"的是长期记忆召回**（条件触发）。
> 想让她"记性变好"，优先级最高的是把召回从条件触发改成私聊常带。

# 修正与补充（同日 16:40 实地核查后）

## ❌ 修正 1：「长期记忆不进 prompt」是错的

上一版说长期记忆只在「记忆意图」时才召回。实地查证：

```python
# ai_group.py:2805
archive_prompt = ltm.archive_text(mem_scope, query=user_text)
```

**固化后的长期事实（203 条）每轮都进 prompt**，走的是 `archive_prompt` → 慢变块 → 稳定前缀。实测输出 1107 字符（≈775 token）。

所以「她记不记得你」这件事，**长期事实一直在起作用**，不依赖意图触发。

真正的条件触发是 `recall_memory()` —— 那个读的是**另一套存储**（消息流水），见修正 2。

## ❌ 修正 2：两套 long_memory 不是"分叉 bug"，是两层设计

| 模块 | 存储位置 | 内容 | 用途 |
|---|---|---|---|
| `plugins/long_memory.py` | `memory/长期记忆.json`（203 条） | LLM 固化的**事实摘要** | 进 prompt（archive_text）+ 可视化 |
| `long_memory.py`（根目录） | `%APPDATA%/.../long_memory/`（2022 条） | **原始消息流水**，按日/周/月/年分层 | 按需召回（recall） |

两者不是同一份数据，也不是冲突关系：

- 固化层负责「提炼成事实」，答"她记不记得"
- 流水层负责「翻原始对话」，答"你上周具体说了什么"

昨天我的三项改动（kind / 字段保留 / 激素衰减）都在 `plugins` 版，**而固化确实走 plugins 版**（`ltm = plugins.long_memory`），所以是生效的。

## ✅ 修正 3：已修一个真实 bug

`archive_text()` 里 profile 注入块被**复制了 4 份**：

```python
_pf = get_profile(key); if _pf: body = f"「对ta的了解」{_pf}\n" + body
_pf = get_profile(key); if _pf: body = f"「对ta的了解」{_pf}\n" + body
_pf = get_profile(key); if _pf: body = f"「对ta的了解」{_pf}\n" + body
_pf = get_profile(key); if _pf: body = f"「对ta的了解」{_pf}\n" + body
```

每轮 prompt 里「对ta的了解」重复 4 次，实测白烧 ≈300 token/轮。

已去重为 1 次（实测 `重复次数: 1`）。

## 结论更新

> **底层逻辑是通的**：
> - 人设 / 长期事实 / 状态 / 历史 / 人格内核 —— 全部每轮进 prompt
> - 消息流水召回是补充，条件触发（合理，因为成本高）
>
> 真正该做的不是"加无条件召回"，而是**减少 prompt 里的浪费**（重复块、冗余格式）。
