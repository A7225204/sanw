## 六、观察项（不影响本次验收，供后续排期）

1. **`timeRange` 恒为 `{min:0, max:0}`**：新实现硬编码；前端 `StarfieldView` 用节点自身 `t` 自算时间窗（`timePct` 过滤），**不消费该字段**，故无功能影响；但与「返回结构不变」的语义有出入，建议后续填真实 min/max。
2. **星尘亮度动态范围被数据吃满**：`brightness = 0.36+0.20*recency`，实测 0.548~0.560（数据 recency 全接近 1），公式下界 0.36 用不到 → 星尘间亮度几乎没有区分度。若想星尘更有层次，建议把 `importance` 混入 brightness。
3. **`scope:douyin` count=0**，只有核心没有星尘（合法，但前端会出现一颗秃核心）。
4. **服务重启并发**：验证窗口内有另一条重启命令同时操作 8090，PID 多次变化；已确认最终监听实例（PID 44952，01:15:35 冷启动）载入新代码，且接口与进程内结果一致。
5. **视觉复验**：本报告未重复 t2 的 headless Chrome 截图（t2 已提供「核心带星尘盘 / cort 光晕 0.4995→0.7666 / hover 高亮边 alpha 0.317 / 默认连线不可见」的截图证据）；本次以「构建产物已被服务端 200 提供 + 接口数据达标」作为等价证据链。
