# 游戏角色「跨界」成本分析报告

> 口径：让「大肥鱼」这个角色（或任意一个已接入的角色）从当前游戏进入另一款游戏，需要花多少钱。
> 数据来源：本机 `shared_memory.db` 的 `token_usage` 真实账单 + 现有代码实现（`tools/pvz_live.py`、`plugins/ai_group.py`）。
> 撰写时间：2026-11-01 19:05　|　币种：人民币

---

## 一、先分清三种「进入」

「角色进入另一个游戏」在成本上完全不是一件事，先对号入座：

| 路径 | 含义 | 技术形态 | 成本量级 |
|---|---|---|---|
| **A. 同类网页游戏** | 目标游戏跑在浏览器里、暴露内部状态（当前 PvZ 就是这种） | 复用 `pvz_live.py` 架构：JS 读状态 + JS 点操作 + 事件流 | **一次性 1~3 人天，运行几乎免费** |
| **B. 视觉识别驱动** | 目标游戏只有画面（模拟器/客户端/手机投屏） | 截图 → 视觉模型 → 坐标点击 | **一次性 5~10 人天，运行 ¥3~4/局** |
| **C. 商业角色授权** | 官方意义上的"我的角色进到别人的游戏" | 版权方授权、皮肤/数值互通 | **¥10 万起，且多半不授权个人** |

> 你现在这套（`pvz_live.py` 300 行 + `ai_group.py` 里 80 行解说）走的是 **A 路线**，所以「进入下一个游戏」的成本主要看目标游戏属不属于 A。

## 二、A 路线：同类网页游戏（推荐）

### 2.1 为什么便宜

现有实现压根不"看"画面：

```python
URL = "http://127.0.0.1:8091/"          # 游戏页面
ST_JS  = "() => { ... window.oS.SunNum ... window.$Z ... }"   # 直接读内存里的状态
TICK_JS = "() => { ClickSun(k); ... }"   # 直接调用游戏自己的函数操作
```

- **没有视觉模型调用** → 每帧成本 0
- **没有 OCR** → 每帧成本 0
- 只有"解说"这一步会花钱（文本模型 + 语音）

### 2.2 一次性投入

| 工作项 | 工时 | 说明 |
|---|---|---|
| 找一款同类网页游戏并确认它暴露状态 | 0.5 天 | 关键前提，找不到就只能走 B |
| 写读状态脚本（`ST_JS` / 决策 `TICK_JS`） | 1~2 天 | 按 PvZ 的 300 行规模估 |
| 写事件流 + 解说接入 | 0.3 天 | 直接复用 `pvz_events.jsonl` 那套 |
| 调优（胜率、解说语气） | 0.5~1 天 | 可选 |

**合计 2~4 人天**。按外包 600 元/人天算：**¥1,200 ~ ¥2,400**；自己做则只有时间成本。

### 2.3 运行成本（按真实账单推）

| 项 | 单价 | 每局用量 | 每局成本 |
|---|---|---|---|
| 解说 LLM | 实测 `memory_merge` 499 次 ¥1.18 → **¥0.0024/次** | 每 45 秒 1 条 × 10 分钟 ≈ 13 次 | **¥0.031** |
| 语音 TTS | `TTS_PRICE_PER_1K = 0.30` 元/千字 | 3 条语音 × 30 字 ≈ 0.09 千字 | **¥0.027** |
| 游戏驱动 | 本地进程 | 全程 | **¥0** |
| 视觉识别 | 不走这条路 | — | **¥0** |
| **合计** | | | **≈ ¥0.06/局** |

按月估：

| 频率 | 月成本 |
|---|---|
| 每天 3 局 | ¥5.4 |
| 每天 10 局 | ¥18 |
| 每天 20 局（连着播） | ¥36 |

> 对比：他日常聊天一天的 LLM 花费实测是 ¥0.03~1.43（见附表），**游戏解说的开销比聊天还低**。

## 三、B 路线：视觉识别驱动

目标游戏没有可读状态，只能"看屏幕点鼠标"。

### 3.1 一次性投入

| 工作项 | 工时 |
|---|---|
| 截屏/窗口定位/坐标映射 | 1~2 天 |
| 视觉模型接入（识别僵尸、阳光、卡槽） | 2~4 天 |
| 状态机 + 点击执行 + 异常恢复 | 2~3 天 |
| 调优（误识别、掉帧、抗遮挡） | 1~2 天 |
| **合计** | **6~11 人天 → ¥3,600 ~ ¥6,600** |

### 3.2 运行成本

视觉调用单价 `IMAGE_CALL_PRICE = 0.20 元/次`（真实账单：6 次 ¥1.20）。

一局 10 分钟，按 3 秒一帧决策：

| 项 | 用量 | 成本 |
|---|---|---|
| 视觉识别 | 200 帧/局 × ¥0.20 | **¥40.0** |
| 解说 LLM | 13 次 × ¥0.0024 | ¥0.03 |
| TTS | 3 条 | ¥0.03 |
| **合计** | | **≈ ¥40/局** |

即使把帧率降到 5 秒一帧（120 帧），也要 **¥24/局**；每天 10 局 = **¥240/天 ≈ ¥7,200/月**。

> 这就是为什么现有实现宁可写 JS 注入也不做视觉——**成本差 600 倍**。

## 四、C 路线：官方角色授权互通

如果你问的是"让我的角色以官方身份进入别人的商业游戏"（皮肤、联动、角色数据互通）：

| 成本项 | 量级 | 说明 |
|---|---|---|
| 版权/授权费 | ¥10 万 ~ 数百万 | 中小厂联动案例普遍 10 万起 |
| 美术改造 | ¥2 万 ~ 10 万 | 角色要适配对方的骨骼/风格/分辨率 |
| 数值与平衡 | ¥1 万 ~ 5 万 | 对方策划要评估强度 |
| 法务/IP 审核 | ¥1 万 ~ 3 万 | 双方合同、分成条款 |
| 分成 | 流水的 10%~30% | 通常是主要成本 |
| 周期 | 3~6 个月 | 排期是最大成本 |

**结论：个人/小团队基本走不通**，除非你本身就是 IP 方或有商务资源。

| | A 网页状态读 | B 视觉识别 | C 官方授权 |

## 六、决策建议

1. **优先找 A 类目标游戏**：判断标准只有一条——能不能在浏览器控制台读到游戏状态（`window.xxx`）。能，就是 2 人天 + 每局 6 分钱的事。
2. **B 路线只在"没有退路"时用**，且必须降到 5 秒一帧以上、只在关键帧识别（例如"僵尸出现"时才看一眼），把每局压到 ¥5 以内。
3. **C 路线不用考虑**，除非以后有商业合作。
4. **先做成本护栏**：给游戏解说加一个日预算上限（例如 2 元/天），超了自动降级为纯文字、再超就停。现在 `token_meter` 已经有记录，加个判断即可。

## 七、如果只想"试一下"

最小验证成本：

- 找一个 A 类网页游戏（半天）
- 复制 `tools/pvz_live.py` → 改 `ST_JS` / `TICK_JS`（1 天）
- 跑 3 局，观察事件流与解说是否成立（**花费 < ¥0.2**）

**总计：1.5 人天 + 不到 2 角钱**，就能判断这条路走不走得通。
