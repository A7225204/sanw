## 二、当前 prompt 的四层结构（决定缓存边界）

`plugins/ai_group.py · _compose_chat_messages()` 的布局顺序就是缓存优先级：

```
① system(稳定前缀)      persona.md + 人设 + 规则   ← 逐字节稳定才缓存
② history 真实多轮      只增不改（前缀缓存的核心）
③ extra_blocks           成长 / 日期 / 天气 / 回忆 / 群聊近况 / 人格内核
④ volatile_prompt        今日状态 / 心情 / 关系 / 性别 / 别复读
⑤ time_block             每轮必变（放最尾巴）
⑥ user                   当前消息
```

**DeepSeek 前缀缓存的规则**：从第 1 个 token 开始连续匹配才有折扣。一旦某处变了，**它之后的所有内容全部失效**。

所以：

- ① 变了 → 全废
- ② 变了（插一条历史）→ ②之后全废，但 ① 仍命中
- ③ 变了 → ③之后全废，①② 命中
- ⑤ 每轮变 → 无所谓，它后面只有 user

## 三、人格内核（soul）的位置对不对？

**对的。** 我把 `soul_aggregation.prompt_block()` 注入在 `_extra`（第 ③ 层），位于历史之后。

影响面：

```
人格内核每晚 3:10 变一次
→ 当晚第一次请求：命中率 = 前缀① + 历史②（通常 80%+）
→ 之后的请求：③ 又稳定了，继续命中
```

如果把它放进 ①（稳定前缀），那天每变一次就**整套历史缓存全废**，代价大几十倍。

### 但有一个隐患

`_extra` 里现在混着四样东西，变化频率完全不同：

| 内容 | 变化频率 |
|---|---|
| 人格内核（soul） | 每天 |
| 成长条目（growth） | 每次固化（2 小时） |
| 日期 / 天气 | 每天 / 每几小时 |
| 回忆 / 群聊近况 | **每轮**（取决于上下文） |

按缓存理论：**变化越慢的越该靠前**。现在它们的顺序如果被打乱（比如"每轮变"的回忆排在"每天变"的人格内核前面），那么人格内核永远命中不了。

## 五、提高命中率的措施（按 ROI 排序）

### ① 少重启 bot（ROI 最高）

每次重启 = 所有群的缓存清零 + 冷启动。

```
今天重启 ~12 次 × 每次损失约 1.5 万 tokens 的折扣 ≈ 命中率 -25 个百分点
```

**做法**：改前端/后端代码不影响 bot 的模块（`dashboard/`、`dashboard-web/`）**不用重启 bot**；只有改 `plugins/` 才需要。

### ② 稳定前缀加指纹保护

代码里已有 `_fp8()` 但只打日志。建议：**前缀指纹变化时打 WARNING**，能立刻发现"谁把前缀改了"。

```python
if _fp8(stable_prompt) != _last_fp:
    logger.warning(f"[缓存] 稳定前缀变化 {_last_fp} → {new_fp}")  # 每次变化都意味着全量冷启动
```

### ③ extra_blocks 按变化频率排序

当前顺序 = 注入顺序。建议固定为：

```
慢 → 快
人格内核（每天） → 成长条目（每 2h） → 日期/天气（每天） → 回忆/群聊近况（每轮）
```

只要"每轮变"的块排在最后，前面的都能命中。

### ④ 人格内核保持"一天一变"

现在 soul 只在 3:10 聚合时更新，符合。**不要**做成"每条消息实时重算"——那会让第 ③ 层每轮失效。

### ⑤ 固化后的特质可以进稳定前缀（收益大、但要设计）

如果某些 traits 连续 N 天不变（比如"嘴硬心软"已经稳定一周），可以把它**冻结进 persona.md 的稳定区**：

```
稳定前缀  ← 已冻结的 3~5 条最稳特质
extra     ← 每天仍在变的新特质
```

这样每天变化的部分变小，前缀命中率更高。但这需要「特质稳定度」统计（连续多少天没被删改）。

## 六、监控建议

现在有 `token_usage` 表，但**没有自动告警**。加一行 cron：

```python
# 每天 23:50 记录当天命中率，低于 70% 就在日志里 WARNING
async def _cache_health():
    hit = 当天 cached / prompt
    if hit < 0.70:
        logger.warning(f"[缓存] 今日命中率仅 {hit:.1%}，检查是否频繁重启或前缀变动")
```

## 七、一句话总结

> **人格进化本身对缓存的伤害很小**（一天一次、位于尾部）；
> **真正吃掉命中率的是重启**（今天 12 次重启把 86% 打到 61%）。
> 所以：**能热改的不重启，必须重启的攒着一起重启**。
