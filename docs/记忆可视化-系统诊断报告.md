## 2) 故障记录：白屏根因、修复位置、验证方式

### 2.1 根因（t5 复盘）

用户看到的「卡在加载详情…」不是整页白屏，而是**详情面板 isLoading 长挂**。链条是：

1. 旧 bundle 的 detail 请求 `retry: 3`（1s/2s/4s 退避）；期间 `isLoading` 一直为 true。
2. `soul:*` 的节点 id 是**按位置索引**的：03:36 快照里有效的是 `soul:rule:0..13`，03:37 之后规则列表缩到 6 条 → `soul:rule:8..13` 变 404。
3. 404 × 3 次重试 ≈ 7s 才显示错误 —— 用户感知就是「白屏/永远在加载」。

网页本身有内容；排查时另有两个独立问题：`pick()` 用旧尺寸公式（`(0.022+0.062*size)*(1400/camDist)`）算拾取直径，中心球 22000 号时直径达 **424,362 px（585×画布高）**，点正中永远选中 10px 内的行星 `soul:rule:2`；`TreeView` 的 G6 实例在 `render()` 未完成时就被 `destroy()`，控制台每次加载报 2 条 error（含未捕获 TypeError）。

### 2.2 修复位置

| 问题 | 文件 | 改动 |
|---|---|---|
| 404 长挂 | 前端请求层（captain 改） | `retry: false`，404 后 ≤1s 显示「详情加载失败 + 节点 id + 重试」 |
| soul id 越界 | `server/memory_viz_persona.py` persona_view | 编号按「类内索引」从 0 开始（`soul:rule:0..5`），14 个 soul 节点详情全 200 |
| 点中心选中行星 | `dashboard-web/src/features/memory-viz/StarfieldView/starfieldRenderer.ts` · `pick()` | 拾取直径改用实际 `sizes[i]`；行星优先轮只在比核心更靠近鼠标时才抢占 |
| G6 控制台报错 | `TreeView/TreeView.tsx` | cleanup 延后到 `render()` 结束再 `destroy()`，并 catch 被打断的 render |

### 2.3 验证方式
