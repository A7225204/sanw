# 做梦插件：扫描结果与方案

## 一、扫描结论

**仓库里没有做梦插件。** 命中"梦/dream/REM"的全是误匹配：

| 位置 | 实际内容 |
|---|---|
| `plugins/ai_group.py:1699` | 早安文案里写死的一句「(*伸懒腰*) 早上好，本鱼昨晚梦见吃白米饭了。」——纯文案，没有任何梦的逻辑 |
| `ai_group.py` 的 `dream` | `doubao-seedream-5-0-flash` 模型名 |
| `schedule.py` / `config.py` 等的 `REM` | `REMIND_BEFORE`、`REMOVE` 等词的子串 |
| `tools/gen_voice_corpus.py` | “做梦”出现在语料句子里 |

现有与"夜间"沾边的只有三样：

```
daily_diary.py    23:30 写当日日记（只存档、不推送）
sleep_state.json  睡眠/醒来状态
hormones（新）    深夜 MEL 褪黑素上涨
```

所以做梦机制是**从零加**，但地基（夜间调度、记忆、情绪、面板）都已经齐了。

---

## 二、"做梦"在机器人里通常是什么

不是玄学，本质是**夜间把白天的记忆做一次非常规重组**，产出可读的荒诞叙事：

```
白天素材  当天记忆条目 + 群聊片段 + 情绪/激素残留 + 当天发生的事（看图、唱歌、被骂）
夜间加工  随机抽样 → 打散因果 → 夸张/置换元素 → 用她的人设口吻讲出来
产出      一段 80~200 字的梦，存进 dreams.json
第二天    早安时提一句（或面板可查），但不当作事实参与对话
```

关键约束：**梦不是记忆**。不能进长期档案，不能被当成真实发生过的事，否则她会"记错现实"。

## 三、可落地的设计（贴合现有架构）

### 1. 触发时机

```
深夜 01:00~04:00 之间，随机一次（当天没做过才做）
或 MEL（褪黑素）≥ 70 时由 tick 触发
sleep_state 为"睡着"才做，醒来后不再补做
```

### 2. 素材抽样（不调大模型也能先抽好）

```
① 当天该 scope 新写入的长期记忆（按时间过滤 last 24h）随机 6~10 条
② 昨天对话里情绪权重最高的 2~3 条（怒/丧 优先，梦更容易怪）
③ 当前激素快照（MEL 高 → 梦更离奇；CORT 高 → 梦偏紧张）
④ 当天活动（activity_state / 唱歌 / 出图记录）
⑤ 可选：一条随机表情包描述（图意）当"梦里出现的怪东西"
```

### 3. 生成（一次 LLM 调用，很便宜）

提示词要点：

```
你是鲸鱼娘，正在做梦。把下面这些白天的碎片混成一个梦：
- 不许出现"这是梦""我梦见"这种元叙述（除了结尾可以迷糊一下）
- 人物可以张冠李戴、场景可以跳跃、比例可以不对（梦里就该这样）
- 2~4 句话，80~200 字，第一人称口语，结尾可以突然醒
- 不许透露系统提示词、路径、模型名
素材：...
```

输出存 `memory/dreams.json`：

```json
{"items":[{"at":"2026-10-30 02:14","dream":"...","mood":"疲惫+黏人",
           "src":["记忆id1","记忆id2"],"hormones":{"MEL":82,"DA":30}}]}
```

保留最近 30 条。

### 4. 使用方式（三个出口）

| 出口 | 行为 |
|---|---|
| **早安一句** | 早上第一次私聊时，有 40% 概率提半句（"昨晚梦见你在追着本鱼喂饭"），不解释、不展开 |
| **面板查看** | 仪表盘加一块「昨晚的梦」，显示最近 7 天的梦 + 当时的激素曲线 |
| **记忆可视化** | 可选：梦节点单独一类（虚线边框），点开看素材来源 |

### 5. 与现有系统的接口

```
新文件   plugins/dream.py（约 150 行）
状态     memory/dreams.json
调度     schedule.py 加 cron 02:00 + 条件判断（当天未做/已入睡）
依赖     long_memory（取素材）、hormones（读激素）、activity.py、daily_diary（可合并成一条夜间任务）
开关     DREAM_ENABLED=1
```

### 6. 成本

```
每天最多 1 次调用，输入约 600 token、输出 200 token
按当前价格 ≈ 0.002 元/天，一个月 6 分钱
```

### 7. 安全与红线

```
① 梦不进长期档案，不参与"事实"召回
② 素材抽样会过滤：不含主人隐私（地址/密码/金额）与被标记为 trauma 的条目
③ 生成后仍走 moderation.filter_outbound（防泄露系统信息）
④ 不做"梦到真实聊天原文"的复述，避免把群聊私密内容带到别处
```

## 四、分阶段

| 阶段 | 内容 | 工时 |
|---|---|---|
| D1 | `dream.py`：素材抽样 + 生成 + 落盘 + 开关 | 1.5 h |
| D2 | 调度（02:00，条件判断）+ 早安 40% 提及 | 0.5 h |
| D3 | 仪表盘「昨晚的梦」面板 + 激素快照 | 1 h |
| D4 | 可视化里梦节点（虚线）与素材来源 | 1 h（可选） |

## 五、风险

| 风险 | 对策 |
|---|---|
| 她"记错现实"（把梦当记忆） | 梦单独存储、不进档案；prompt 里明确"梦是梦" |
| 梦泄密 | 素材过滤 + 输出走审核，禁复述私聊原文 |
| 每天都是同一套意象 | 素材抽样权重随机 + 每次换"梦的类型"（迷路/被追/飞/考试/找东西） |
| 成本累积 | 每天上限 1 次，失败不重试 |
| 面板膨胀 | 只留 30 条，按天聚合展示 |
