## 4) 坐标 ↔ 渲染尺寸：拾取半径已达画布的 5.9×/585×，行星被中心光晕吞掉（已知问题，实锤）

渲染器换算（`starfieldRenderer.ts`）有两套公式：

```ts
// 拾取半径（px，不截断）：line 859
pxDia = (0.022 + 0.062 * sf.size) * (1400 / camDist)
// 实际绘制点大小：line 504（上限 260px）
gl_PointSize = min(aSize * pulse * (1400 / -mv.z), 260)
```

默认视距 4.5（persona-only 场景 `sceneRadius≈0.5 < 0.6` → `fitDistance=4.5`），画布 1092×725：

| 节点 | 后端 size | pxDia（可点直径） | 相对画布高 | 相对画布宽 | 实际绘制点数 |
|---|---:|---:|---:|---:|---:|
| persona 中心 | 22000 | **424,362 px** | **585.3×** | **388.6×** | 62 px |
| soul 行星 | 220 | 4,250 px | **5.9×** | 3.9× | 9.3 px |
| 星尘 | 90 | 1,743 px | **2.4×** | 1.6× | 9.3 px |

视距缩到 1.0 时更夸张：中心 **1,909,631 px（2634× 画布高）**、行星 26.4×、星尘 10.8×。

- 若按「size 直接当像素半径」的另一种口径：中心 22,000 px = **30.3× 画布高**，行星 220 px = 0.30×，星尘 90 px = 0.12×。
- 实测后果：行星轨道半径只有 0.053~0.063 世界单位，而中心光晕 sprite 是 0.68 世界单位 → **行星整个埋在中心光晕里**；
  真机点画面正中，选中的是 `soul:rule:2`（行星）而不是 `persona:me`（人核）。

**结论：这是 P0——渲染尺寸被 260px 截断「看起来正常」，但拾取半径按原始 size 线性放大到画布的 2.4~585 倍，点选不可控、人核点不到。**
