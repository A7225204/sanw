# dsh-see-now 对比分析报告（vs 大肥鱼的「看视频」）

> 分析时间：2026-11-02 17:30
> 对象：<https://github.com/SAOS-3624/dsh-see-now>（v0.0.5，82★，Apache-2.0）
> 对照：`D:\qq-ai-bot` 的 `plugins/media_fetch.py` / `plugins/douyin_fetch.py` / `plugins/storyboard.py`

---

## 一、一句话结论

**不是替代关系，是两个物种。**

- **see-now** = 「实时看着屏幕/摄像头」的**采集与选帧器**：每帧打变化分，只留值得看的帧，拼成一张图省 token。**不听声音、不下载、不缓存、不理解语义**。
- **大肥鱼的看视频** = 「看完一条抖音/B站视频并说出内容」的**批处理管线**：下载 → 分镜/抽帧 → 识图 + 字幕 + 口播转写 → 文本缓存 → 用来评论/学习。

要比"**选帧算法和 token 效率**"，see-now 更先进；
要比"**看懂一段视频讲了什么**"，你现在这套更完整（它有字幕和 ASR，see-now 一个都没有）。

## 二、see-now 是什么（拆解）

| 维度 | 做法 |
|---|---|
| 采集 | 唯一一处 spawn ffmpeg，rawvideo 管道；`ddagrab`（桌面复制 API）0.28 核 / `gdigrab` 0.45 核，12fps → 800×450 |
| 变化分 | 缩到 64×36 网格，HSV 三通道加权绝对差，0~255，约 **0.2ms/帧** |
| 选帧 | ①**切点**：score ≥ 12 且 > 2.5×前后帧且距上一刀 ≥0.4s；②**积分**：每帧累加分，攒够 4×12×3=144 录一帧；③**兜底**：静止 20 秒给一张"确实没变" |
| 档位 | 按"每秒留几帧"把格子定成 1/k（k=1..8），k≈√(T·F)，带 7 道阈值 + 滞回 |
| 拼图 | `pack.js` **DP 装箱**把大小不一的格子铺满画布；`sheet.js` 合成 PNG 并烧帧号 |
| 成本 | 800×450 一张 ≈ **233 token**；一张塞 4 帧和 8 帧**同价** |
| 交互 | `watch`（阻塞到攒够一张）/`peek`/`start`/`stop`/`status`；`pace` calm/normal/dense；`scene` 逐场景；`quality` 四档；`minFrames`；`seconds` 上限 300 封顶 860 |
| 附加 | 语音事件总线 + TTS 适配器（`say` 是唯一通道）、悬浮窗示例、常驻唤醒循环、85 条测试 |
| 平台 | Node ≥20 + ffmpeg；**Windows 优先**（ddagrab/gdigrab）；Linux/macOS 要自己补采集源 |
| 已知短板 | 只认"像素变了"不认"语义变了"；无跨帧语义去重；无 ASR；无持久化 |

## 三、你的「看视频」现状（拆解）

| 路径 | 做法 |
|---|---|
| 抖音 | 浏览器截接口拿地址 → 下载 → **固定抽 3 帧**（20%/50%/80%，720p）→ 识图 → SenseVoice 转写 → 合并文本 |
| B站 | yt-dlp 1080P → `storyboard` 分镜：ffmpeg scene 分数找切点 → 按"切点密度"**等分 9 格** → 每 300s 一张宫格 + 烧格号/时间码 → **挑 3~6 张**识图 → B站字幕引用 + SenseVoice 转写 |
| 缓存 | `data/media_cache/<平台>/<id>.mp4` + `.txt`，45 天；命中直接读文本 |
| 落点 | `_describe_images` 识图（谷歌→本地→硅基→火山），结果进评论/学习/追剧档案 |

**它的强项（see-now 没有）**：
- **声音**：字幕（带时间码）+ 本地 ASR 口播稿 —— 对"口播为主"的视频是决定性信息
- **闭环**：下载/平台适配/缓存/成本控制（限制识图张数）/和人格评论链路打通
- **跨平台**：不依赖 Windows 抓屏，B站/抖音都能跑

**它的弱点（see-now 明显更强的地方）**：
- 抖音路径**固定 3 帧**：长视频、慢节奏、镜头运动的信息会漏；片头黑场/重复帧又浪费
- B站宫格是**等分格子**（按切点密度），不是"自适应大小 + DP 装箱"—— 信息密集的段落格子并不会变大
- 切点用 ffmpeg `scene` 分数：see-now 源码里明确说，同一段测试片用它的 HSV 方案 **9/9 命中**，`ffmpeg scdet` 只有 **4/9**（对"同亮度换色"失明）
- 没有"变化量积分"兜底：一镜到底、缓慢推进的视频没有切点，只能靠窗口等分

## 四、逐项对比

| 维度 | see-now | 大肥鱼看视频 | 谁更好 |
|---|---|---|---|
| 用途 | 实时陪看屏幕/摄像头 | 点播看完一条视频 | 不同场景 |
| 输入 | 屏幕 / 摄像头 / 视频文件（实时管道） | 抖音/B站链接（下载） | 各有胜负 |
| 选帧算法 | 切点 + 积分 + 兜底，因果、逐帧 | 抖音固定 3 帧；B站 ffmpeg 切点 + 等分 | **see-now** |
| 拼图 | 自适应档位 + DP 装箱 + 烧帧号 | 固定 9 格等分 + 烧时间码 | **see-now**（B站接近） |
| token 口径 | 明确（233/图，4~8 帧同价） | 有意识（限 3~6 张），但没量化单图成本 | **see-now** |
| 听懂内容 | ❌ 无音频 | ✅ 字幕 + ASR | **你** |
| 语义/结构化 | ❌ 纯视觉 | ✅ 标题/文案/口播/分镜文本 | **你** |
| 缓存复用 | ❌ 无 | ✅ 45 天，命中不重算 | **你** |
| 实时性 | ✅ 12fps 连续、按节奏叫醒 | ❌ 只能事后批量 | **see-now** |
| 部署成本 | 装插件 + ffmpeg + 桌面 profile + 重启 | 已在 bot 里跑 | 平 |
| 平台 | Windows 优先 | 跨平台 | **你** |
| 工程质量 | 85 测试、DP 装箱、文档/调试窗齐全 | 单文件脚本、无测试 | **see-now** |

## 五、值得抄的三件事（按性价比排序）

1. **切点判据换成"绝对地板 + 尖峰 + 不应期"**
   落点：`plugins/storyboard.py · scan_cuts()`（现在是 ffmpeg scene 分数）。
   好处：解决"同亮度换色漏检"，同时不被运动噪点误切（see-now 实测 9/9 vs 4/9）。

2. **等分格子 → 档位 + DP 装箱**
   落点：`alloc_cells()` + `compose_sheet()`。
   好处：信息密集段给大格、稀薄段给小格，同样画布塞更多有效信息；token 不变。

3. **抖音固定 3 帧 → 变化分挑帧拼一张 2×4**
   落点：`plugins/douyin_fetch.py · _frames()`。
   好处：避免黑场/重复帧，长视频覆盖更全；1 张图（≈233 token）替代 3 张图。

> 第 1、2 条是纯本地算法改动，不需要动 bot 的对话链路；第 3 条只影响抖音分析质量。

## 六、要不要装 see-now

**装，但别指望它替代看视频。**

- 它适合的场景：**桌宠/DSH 助手实时看着你的屏幕**（你在剪视频、打游戏、看直播时它能接话），以及"陪看"类语音播报。
- 它不适合的场景：**"帮我看完这条抖音/B站并评论"** —— 它不下载、不听声音、没有缓存，也没有平台适配。
- 两者可以并存：bot 用现在的 `media_fetch` 管线；DSH 桌面侧装 see-now 做实时陪看（还能复用同一份 TTS 适配器）。

## 七、风险/注意

- see-now 依赖 **ffmpeg + Windows 抓屏**，和你的 bot 是两套进程环境；
- 它是 `desktop` profile 插件，**要重启 DSH 生效**；不影响 QQ 机器人；
- 它是 0.0.5 的新仓库（2026-11-01 建），更新频繁，装之前建议先 `git clone` 到本地看 `scripts/install-dev.mjs` 拷了哪些文件；
- Apache-2.0，商用/二次开发都没问题（保留 LICENSE + NOTICE）。
