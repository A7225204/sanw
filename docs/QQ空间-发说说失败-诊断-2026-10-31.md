## 6) 可复现的具体失败点（带行号）

**F1（确定可复现，最坑）过期票回落复活**
`qzone_sync.py:159-165 / 182-212` 回落读取 `data/qzone_cookies.json`（10-24 02:12，已过期），而 `qzone_sync.py:227-234` 清 cookie 只删 `memory/qzone_cookies.json`。
→ 无论清多少次，下一次发布又会读到那张 7 天前的废票，再 -3000。复现：
```bash
ls -l data/qzone_cookies.json          # 10-24 02:12，18 个 cookie，含 p_skey（已过期）
python -c "from plugins.qzone_sync import _load_cookies; d=_load_cookies(); print(d.get('saved_at'), bool(d.get('cookies')))"
# memory 文件缺失时输出: （列表格式导出） True
```

**F2（captain 已修，仍留残余风险）窗口保存只认 URL**
`tools/qzone_window.py:93` 保存条件仍是 `"user.qzone.qq.com" in pg.url`；而 `qzone_sync.py:253-256` 自己写明「空间页经常被重定向回 i.qq.com，只要 cookie 有 uin+p_skey 就还能用」。
→ 若主人登录后停在 i.qq.com 且**不关窗**，仍不会保存；更糟的是 `MAX_OPEN` 超时分支（`qzone_window.py:87-89`）直接 `break`，**不经过关窗抢救逻辑**，360 秒后登录态白做。建议把"URL 判断"统一换成"cookie 齐不齐"，并在超时分支也抢救一次。

**F3（本次新范围：4 个"残留进程"是误报）**
- 现在真实残留：`python*qzone_window.py` **0 个**；`msedge --user-data-dir=...qzone_profile*` **0 个**。
- 用 ai_group 同款检测（`ai_group.py:6365-6370`，PowerShell 匹配**任意进程**命令行含 `qzone_window\.py`）在诊断 shell 存活时执行，返回 **4**；同一时刻 python 口径真实窗口数为 **0**。
→ 任何命令行里提到过这个文件名的进程（grep/tail/python 诊断脚本、agent 的 bash）都会被算成"窗口还开着"。后果：
  1. `ai_group.py:6371-6375`：判定"已在运行"→ **不再拉起窗口**，但仍然回复「窗口弹出来了」→ 主人看不到窗口却以为已登录；
  2. `qzone_sync.py:422` `_login_window_open()`（python 口径）也会被诊断脚本的 `python.exe` + `python3.13.exe` 双进程对误触发 → 发布干等 2 分钟后返回「登录窗口还开着」。
→ 建议：改为校验**进程名 + cmdline 精确匹配 `tools\qzone_window.py` 且非诊断**（或用 pid 文件/端口锁），别用"命令行含子串"。

**F4（并发）keepalive 不检查登录窗口**
`qzone_sync.py:238-270` 的 `keepalive()` 直接开无头浏览器用同一个 `qzone_profile_bot`，**没有** `_login_window_open()` 前置判断（对比 `qzone_sync.py:422` 的兜底分支有判断）→ 窗口开着时会用同一个 profile 起第二个浏览器，互踢后照样"拿不到 p_skey"，然后 `qzone_sync.py:419` 把 cookie 清掉（连带清掉刚登录成功的票）。

## 7) P0/P1/P2 汇总

- **P0（已修，待回归）**：窗口关得太快导致登录态不落盘 —— 由 5s 轮询 + 无抢救造成；captain 已改为 800ms + 关窗抢救，15:10/15:11 两次落盘成功。
- **P1-1**：过期票回落（F1）——`data/qzone_cookies.json` 10-24 的废票会在每次清 cookie 后复活，必须加"落盘时间/有效性"过滤或一并清掉。
- **P1-2**：窗口保存仍以 URL 为成功判据（F2），超时分支不抢救；与 `qzone_sync` 的 cookie 判据不一致。
- **P1-3**：窗口占用检测误报（F3）——`ai_group` 用"任意进程命令行包含文件名"，会把诊断脚本当窗口；会导致"扫码了却弹不出窗口"。
- **P2-1**：`keepalive()` 与可见窗口抢同一 profile（F4），且失败即清 cookie。
- **P2-2**：`tools/qzone_login.py` 是孤立脚本（profile/路径都与现役流程不同），容易误导后来人；建议删除或标注废弃。
- **P2-3**：7 天内成功 2 次 / 失败 15 次，失败集中在 14–18 点发布时段；建议加"发布前置校验"（captain 已列入 t9）。
