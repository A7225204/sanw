  - **语音/音乐**：`ace_sing` / `ace_sing15` / `seedvc` / `song_mix`
  - **画图**：`image_edit` / `comfy_boot`
  - **游戏**：`game_watch` / `phone_play`
  - **平台**：`boss_job`（求职）/ `qzone_*` / `feishu_bridge`

### P2 · 行为描述偏差

**3. §五 两个"已取消"任务其实还在代码里**
- 手册写 `~~daily_morning~~ / ~~daily_night~~` → "⏸ 已取消（G.23）"
- 实际：`plugins/schedule.py:103` 和 `:114` 仍注册着 cron，靠 `PUSH_ENABLED = bool(TARGET_GROUP)`（`:63`）早退。
- 准确说法应是：**"保留但默认早退（未配 TARGET_GROUP 时不发）"**，不是"已取消"。

**4. §五 漏了 memory_health.py 的定时任务**
- `memory_health_daily`：每天 4:20
- `memory_health_first`：每 13 分钟
- 手册 §五 只覆盖 `schedule.py`，但这两个任务同样在跑，排查"凌晨任务"时会漏。

**5. 今天新增的启动补做不在手册**
- `_catchup_dream()`（`schedule.py:236`）：启动 2 分钟后检查，若已过 2:15 且今天没做梦则补做。
- 这是修复"2:15 重启导致漏梦"的改动，手册 §五 没记。

### P3 · 已确认仍然准确的部分（无需改）

- §十一 指令表：`COMMAND_WORDS` 实测 67 个，与手册"67/67 命中"一致
- §六 全部 11 个 API 在 `dashboard/server.py` 存在
- 端口全在监听：8080 / 8090 / 7801 / 9881 / 8101 / 10086 / 3080
- 常量：`MEM_WEIGHT_START=1.0`、`MEM_WEIGHT_MAX=3.0`、`MEM_DECAY_FLOOR=0.12`、`MIN_SIM=0.32`
- §八 #4 `repair` 无触发源：确认（`hormones.py:53` 有定义，全仓库无 `apply_event("repair")` 调用）
- §八 #5 两套 `long_memory` 并存：确认
