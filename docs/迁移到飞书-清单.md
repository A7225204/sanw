# 从 QQ 迁移到飞书：功能对照与执行清单

> 写于 2026-10-27，触发条件：腾讯开始全面封杀 NapCat 类第三方协议端。
> 当前状态：飞书通道已打通（私聊全功能），QQ（NapCat）保留兜底。

## 一、现在的双通道结构

```
D:\qq-ai-bot（同一个 NoneBot 进程）
├─ NapCat 反向 WS（8080）  → QQ 全功能
└─ plugins/feishu_bridge.py → 飞书长连接（独立线程）
      App ID: cli_aa6a2dc437b8dc1b（用户682301的飞书）
      配置: .env 的 FEISHU_APP_ID / SECRET / OWNER_OPEN_ID / OWNER_UID
```

核心能力（人设、记忆、情绪、食欲）在 `plugins/ai_group.py`，飞书通过
`ai_group.feishu_chat(uid, text)` 复用同一套 prompt，写回同一份记忆
（scope = `private_100000000`）。

## 三、关键卡点：读群全部消息

飞书群机器人默认只在 **@ 机器人** 时收到消息事件。

```
需要：im:message.group_msg（读取群消息）
路径：开发者后台 → 权限管理 → 申请 → 说明用途 → 人工审核
通过 → 群黑话/主动插嘴/被叫醒 全部可迁
不通过 → 群内只能 @ 触发，QQ 的"群感"能力降级
```

替代方案（过不了审核时）：

- 群黑话改为「只学 @ 她时的上下文 + 私聊里提到的梗」
- 主动插嘴改为定时主动发言（不依赖监听）
- 被叫名字就醒 → 改成必须 @

## 四、迁移执行顺序（预计 2~3 天）

```
1. 抽通道接口（半天）
   plugins/channels/base.py: send_text / send_image / send_voice / send_group
   ai_group 里的发送调用改成走接口
2. 飞书适配器补齐（半天）
   群聊事件、图片消息、定时推送
3. 申请 im:message.group_msg（外部等待，随时可做）
4. 功能开关（半天）
   .env: CHANNEL=feishu|qq|both（默认 both，按需切换）
5. 双跑一周，确认飞书侧无缺失后，napcat 降级为兜底
```

## 五、真被全面封杀时的应急步骤

```
1. 确认 NapCat 无法登录（不是本地问题）
2. .env 里把 CHANNEL 切到 feishu
3. 飞书群里把机器人拉进去（群主操作）
4. 通知常聊的群友：以后在飞书找她
5. QQ 侧数据不用动（记忆库是独立的 SQLite/JSON）
```

## 六、不该做的事

- 不要在飞书私信里发 QQ 号/微信号（引流话术会被平台限流）
- 不要用飞书私信给非好友群发（判骚扰）
- 不要把 `%TEMP%\edge_feishu_copy` 目录留长期（里面是登录 cookie）
