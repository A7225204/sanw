# QQ 空间「发说说老失败」修复方案与最小落地

> 执行人：backend ｜ 时间：2026-10-31 15:15–15:30（Asia/Shanghai）
> 依据：t8 只读诊断（docs/QQ空间-发说说失败-诊断-2026-10-31.md）+ 本次代码复核
> 改动文件：`plugins/qzone_sync.py`、`plugins/qzone_auto.py`（只动 qzone 插件与其发布入口）

## 1) 根因判断：凭据链路断，不是续期算法写错

t8 的证据已经足够定性：

| 事实 | 说明 |
|---|---|
| 15:05–15:09 主人扫码后 `logs/qzone_login.log` 零记录、`memory/qzone_cookies.json` 不存在 | 窗口登录成功了，但**保存流程没跑** |
| `output/qzone_live.json` 停在 10-30 18:33 | 旧窗口 5s 轮询 + 关窗即 break，没有"关窗前抢救" |
| 修复后 15:10:16 / 15:11:18 两次落盘，15:13:41 首发成功 | 保存链路修好后立刻恢复 |
| 失败分类：-3000 ×7、cookie 失效被清 ×7、续期拿不到 p_skey ×4、快捷登录失败 ×10 | 全是登录态下游，没有内容被拒/超时 |

所以：**根因是「扫码 → 落盘」这条链路会断**（captain 已在 15:10 修好窗口轮询与抢救）。
续期逻辑本身没有硬错，但有三处把"一次断"放大成"一直坏"：

1. **过期票回落复活**：`_drop_cookies()` 只删 memory 文件，`_load_cookies()` 又回落读 `data/qzone_cookies.json`（10-24 废票）→ 清完又读到 → 再 -3000。**captain 已于 15:15 置空 `COOKIE_FALLBACKS` 修掉。**
2. **keepalive 与可见扫码窗口抢同一个 profile**（F4/P2-1）→ 互踢后"拿不到 p_skey"，接着把刚登录好的票清掉。
3. **失败即清票、且没有"先校验再生成"**：自动发说说每轮先写文案再失败，白烧 LLM，两天就把失败次数刷到 30 行。

## 2) 分场景方案与代价

| 方案 | 做什么 | 成本 | 风险 | 本次是否落地 |
|---|---|---|---|---|
| **A 凭据保鲜** | 每天固定用持久化 profile 刷一次 cookie（已有 08:30 `qzone_keepalive`）；本次再加"cookie 超过 30h 就先续期"（并入 B） | 低：每天一次无头浏览器 ~15–25s | 低：与发布抢 profile（已加窗口判断） | ✅ 部分（沿用已有 cron + 新鲜度续期） |
| **B 失败前置** | 发说说前先校验登录态；缺失/过期先自动续期一次，仍不行就直接提醒扫码，**不生成文案** | 低：纯本地文件检查，0 网络 | 低：误判只会"少发一条"，不会发错 | ✅ 已落地 |
| **C 失败后自愈** | 发布报 -3000 时自动续期并**重试一次**；扫码窗口开着就等窗口落盘，不抢 profile | 低：多等 ≤30s | 低：重试上限 1 次，不会死循环 | ✅ 已落地（在原有基础上加固） |
| **D 落盘校验** | 保存 cookie 前检查 uin/p_skey 齐全，缺了不覆盖旧凭据 | 低：几行判断 | 中：写盘逻辑涉及登录态，改错会存坏票 | ⏸ 未改：`qzone_window.py` 15:10 已带 uin+p_skey 校验和关窗抢救，等效覆盖 |

> 选择 B + C 的理由：不动凭据存储格式、不动登录窗口写盘逻辑，只加"发布前检查"和"失败后的一次自愈"，出问题最多是"少发一条 + 提醒扫码"，不会把能用的登录态写坏。

## 3) 本次改动清单与 diff 摘要

### `plugins/qzone_sync.py`（+约 90 行）

1. **新增 `cookie_status()`**：本地校验 `uin` / `p_skey` / 账号是否机器人号，返回可读原因，不联网。
2. **新增 `preflight(refresh=True)`**：
   - 结构完整且 30h 内刷新过 → 直接放行；
   - 缺失/过期 → 有扫码窗口就等主人扫，没有就**续期一次**；
   - 续期失败返回 `登录态失效：…`，调用方据此提醒扫码；
   - 扫码窗口开着 / 发布锁被占时直接返回（不抢同一个 profile）；
   - 续期有 30 分钟冷却（`_PREFLIGHT_REFRESH_GAP`），登录态一直坏时不会每 10 分钟开一次浏览器。
3. **新增 `_wait_window_cookies(timeout)`**：扫码窗口开着时等它落盘，**不再用无头浏览器抢同一个 profile**。
4. **自愈分支加固**（`_publish_qzone_inner`）：
   - -3000 时：窗口开着 → 等窗口；否则 `keepalive()`；成功后**重试一次**（原逻辑保留）；
   - 失败日志改为「自愈续期失败：…；继续用无头浏览器试一次快捷登录」；
   - 最终兜底文案改为「QQ空间登录态失效，快捷登录也没成功——私聊我发「扫码」登录一次」。
5. **新增常量 `COOKIE_REFRESH_AFTER_H`**（默认 30h，可用 `QZONE_COOKIE_REFRESH_HOURS` 覆盖）。

### `plugins/qzone_auto.py`（+13 行）

- `_tick()` 在**生成文案之前**调用 `qzone_sync.preflight()`：
  ```python
  _ready, _why = await qzone_sync.preflight()
  if not _ready:
      logger.warning(f"[空间自动] 前置校验没通过：{_why}；本轮不生成文案，等主人扫码")
      await qzone_sync.notify_login_needed(get_bot(), int(OWNER), _why)
      return
  ```
- 未通过时**不消耗 LLM、不计失败 streak、不触发 6 小时暂停**，只发一次扫码提醒（`notify_login_needed` 自带每日去重）。

> 未改动：`daily_mood.py`（它的主职责是给主人发私聊，qzone 只是附带通道，生成不浪费）、`qzone_window.py`、`tools/qzone_login.py`、任何其他插件。

## 6) 为什么这样改能减少「老出问题」

1. **失败更早暴露**：登录态问题在**生成文案之前**就被发现（B），不再出现"写了文案、开了浏览器、最后报 -3000"；自动发说说单轮白烧的 LLM 归零。
2. **能自愈一次**：cookie 过期/缺失时先尝试 profile 续期再发（B），发布中遇到 -3000 再续期重试一次（C）。只要 profile 会话还活着，多数情况**不用主人扫码**就能恢复。
3. **不再把好票弄坏**：窗口开着时不再抢 profile（C），避免"续期失败 → 清票 → 连刚登录的票也清掉"的连锁反应；过期备用票已被 captain 停用，清票后不会复活。
4. **用户可见行为明确**：失败信息统一为「私聊我发「扫码」登录一次」，不再把 `-3000` / `快捷登录失败` 裸抛给主人。
5. **不制造浏览器风暴**：前置续期有 30 分钟冷却 + 扫码窗口判断，登录态一直坏的时候也不会每 10 分钟开一次 msedge。
