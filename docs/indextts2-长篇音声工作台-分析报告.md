## 一、一句话结论

**它不是一个"语声更好听"的模型，而是一层"长篇台本 + 多轨音频"的生产工作台**，
必须装在 **IndexTTS2.0 超级优化整合包 V3**（作者：十一君Jun，B站）之上才能跑。
真正决定声音质量的是整合包里的 **IndexTTS2 模型**；这个仓库只做编排层。

所以：
- 想让**她 QQ 里说话更好听** → 关键在换 TTS 模型（IndexTTS2），不是装这个补丁；
- 想做**长音声内容**（有声书 / 广播剧 / ASMR / 视频解说）→ 这套就是现成的成品流程。

## 四、六个真正有价值的设计

### 1. 台本智能导入（最值得借鉴）

`lf_import.py` 的 `split_smart()`：

- 按句末标点切，**括号/引号内部不切**（`depth` 计数）；
- 按上限合并短句（`max_chars`）；
- 超长句再「软切」：优先在深度 0 的逗号/句末切，没有安全切点就整段保留并标 `over`；
- 五类文稿识别（时间轴稿 / 剧本 / 小说 / 指令 / 纯文本）+ 多种分行方案；
- 可选的「高级识别」：按旁白里的「李四说」「李四冷笑：」认人，认不出退回角色A/B；
- 对白符号表（`[]` `【】` `《》` `{}` `「」` `『』` `“”`）可自定义——避免方括号对白被当成备注。

> 对比：我们机器人现在的长文本是按长度/句号硬切，没有"括号内不切、超长软切、认人"这层。

### 2. 逐句状态机（断点续跑 + 修改追踪）

每行 = 独立任务（文本 + 音色 + 情感参数 + 状态 + 时长 + 产物）。
支持：单句生成 / 只生成选中行 / 补全未生成 / 全文生成；按状态/音色/分组筛选；
文本或参数变更会走"签名"（`_sig_canon`）比对，标出改过的句子。
生成期间可排队、可中止（`stop_event`）。

### 3. 情感控制：4 模式 + 8 轴向量

`_engine_kwargs()` 直接映射 IndexTTS2 的 `infer()`：

```
spk_audio_prompt   音色参考音频
emo_mode           0 同音色 / 1 情感参考音频 / 2 情感向量 / 3 情感描述
emo_alpha          情感权重 0~1
emo_vector         8 轴：喜悦 / 愤怒 / 悲伤 / 恐惧 / 厌恶 / 低落 / 惊喜 / 平静
emo_text           情感描述文本（模式 3）
max_text_tokens_per_segment  分段长度
+ 采样参数 do_sample / top_p / top_k / temperature / length_penalty / num_beams /
  repetition_penalty / max_mel_tokens / interval_silence
```

这是 F5-TTS 那条链没有的东西——F5 只能靠参考音频，情绪不可调。

### 4. 多轨时间轴

片段属性：位置 / 时长 / 源起点 / 音量 / 声像 / 淡入淡出 / 播放速度（含"变速到指定时长"）；
可从台本按句序与句间停顿**重排**，只改开始时间不重新生成。

### 5. 空间音频（ASMR 向）

HRIR（KEMAR / KU100 近场）+ 方位/仰角/距离 + 房间混响干湿比；
内置 **13 种运动脚本**（左右往返、绕头圆周、掠过耳侧、头顶环绕、背后低语…）+ 关键帧曲线。

### 6. 工程导出

WAV / MP3 / FLAC / OGG 混音；**REAPER 工程**（含片段位置/裁剪/音量/声像/淡入淡出/自动化）；
**PR / 达芬奇 EDL**；Audacity 分轨 WAV + 标签；stems + `timeline.csv` + `markers.csv`。

| 项 | 说明 |

## 六、对「蓝色大肥鱼」的价值判断

### 不建议直接接进聊天链路

- 我们的语音链是 **本地 F5-TTS(9881) → RVC 派蒙(8101) → silk**，链路短、延迟可接受（F5 单句秒级）；
- IndexTTS2 单句推理更重（同机 12GB 还要和 ComfyUI 抢显存），聊天场景会被拖慢；
- 这套工作台是"离线制作"工具，不是实时服务。

### 但有三处值得用/借

1. **长音声内容**（她的 ASMR / 有声书 / 视频解说 / 广播剧）
   → 独立装、独立跑，不接进 bot；产出的音频再拿去发。这是它最强的地方。
2. **`split_smart` 分段逻辑**
   → 可移植到机器人「长文本朗读/语音回复」的分段里：括号引号内不切、超长软切、超限标记。
3. **情感参数设计（4 模式 + 8 轴）**
   → 以后若把 TTS 换成 IndexTTS2（或其它支持情感向量的模型），这张参数表可以直接照搬；
   甚至可以先在 RVC 侧用"情绪→参考音频"做近似映射（F5 换 ref 音频 = 换情绪）。

### 如果真想升级她的声音

最小路径不是装这个工作台，而是：
1. 先单独装 IndexTTS2 整合包，验证音色/情感质量；
2. 用它的 HTTP 接口在 `tools/local_tts_server.py` 旁边加一个 Provider；
3. 用同一套 `infer()` 参数（上面第四节的字段）驱动；
4. 再决定要不要保留 RVC 变声那一步。

# 附：底座本体 IndexTTS2 Studio（lfandrh/indextts2-studio）扫描

> 仓库：https://github.com/lfandrh/indextts2-studio（B站 @十一君Jun）
> 上面那份"工作台"就是挂在这个包上的补丁；**声音好不好听由它决定**

## 它是什么

IndexTTS2 官方模型的本地化改造版：FastAPI + 原生 JS 的本地工作台，端口 **7860**，
`/api/v1/*` 正式路由，`POST /tts` 用 SSE 推五步进度（加载→参考特征→GPT→s2mel→BigVGAN）。

## 关键数据（作者 3060 Ti 8GB 实测）

| 项 | 数字 |
|---|---|
| 显存常驻 | 约 **5.6 GB**（fp16 三项全开）；两段批处理峰值 7.8 GB |
| 空闲显存 | **0**（模型懒加载，首个请求才载入，约 20~60 秒） |
| 速度 | RTF **0.89**（逐段）/ **0.64**（两段一批）→ 105 秒音频约 93 / 68 秒生成 |
| 500 字中文 | 93.5 s（audio 105.6 s） |
| 短句 | 端到端约 4 秒（RTF 1.36） |

## 它做对的关键优化

1. **BigVGAN 补 `torch.no_grad()`**：单步 128 s → 0.33 s（380×），RTF 11.87 → 1.31 —— 这是它比官方快 7 倍的根本原因
2. **4 项 FP16 开关**（gpt / s2mel / w2v / qwen），其中 `w2v_fp16` 单项省 ~1 GB
3. **参考音频按内容 md5 存盘** → 同音色第二次起跳过 W2V-BERT 特征提取
4. **懒加载 + 可卸载**（`/model/unload` 立即还显存；生成中也能安全卸载）
5. **扩散步数 / CFG 可在线调**（25→10 步：s2mel 31.2 s→10.5 s）
6. **删掉上游 5 个负优化项**（flash-attn 加速在 8GB 上反向加速 95%、torch_compile/cuda_kernel/tf32/deepspeed）

## 情感控制（和 F5-TTS 的本质差别）

4 模式：同参考音频 / 情感参考音频 / **8 维情感向量**（喜悦/愤怒/悲伤/恐惧/厌恶/低落/惊喜/平静 + 权重）/ 情感文本（Qwen0.6B）。

> 这对大肥鱼是个真正的接口：**她的情绪状态可以直接映射成 8 轴向量**（激素/心情 → emo_vector + emo_alpha），
> 不再是"换一段参考音频"这种粗粒度。

## 自带 Agent Skill（值得注意）

仓库内 `skills/indextts2-tts/`：纯标准库客户端、25 个子命令（`doctor` / `synth` / `segments` / `batch` / `tempo` / `presets` / `model` / `unload` …），
专为 DSH / Claude Code 这类 agent 设计，**只走 HTTP、不 import 项目代码**，能装成用户级 skill。

三条硬规则写死在代码里：① 没音色必须停下问人（退出码 2）；② 禁止并行生成（全局锁 + 文件锁）；③ 音频必可找回（`last.json`）。

## 对我们这套的影响（判断）

| 用途 | 结论 |
|---|---|
| 聊天语音（QQ 语音回复） | **可以用，但要解决显存冲突**：它常驻 5.6GB，而 ComfyUI 画图要 9~11GB，二者不能同时常驻 → 要么用完 unload，要么画图前 unload，要么接受切换抖动 |

## 十、显存策略（已确认：**TTS 常驻，画图按需**）

```
常态：IndexTTS2 常驻 5.6GB  ← 聊天随时可用
画图：ComfyUI 加载 Z 模型（9~11GB）→ 出图后调 /free 卸载 → 回到 0
```

落地要点：

1. **画图用完就卸载**：bot 已有 `_comfy_free()`（`POST /free {unload_models}`），
   出图后调一次即可把 ComfyUI 的 9~11GB 还回去；
2. **画图期间 TTS 不抢占**：TTS 是几秒级短任务，若正好同时发生，排队等它跑完即可；
3. **极端兜底**：显存真不够时先 `POST /model/unload` 卸 TTS，画完再懒加载（20~60 秒，后台进行）；
4. **不要两个都常驻**：Z 模型 11.7GB + TTS 5.6GB 必然超 12GB，这是硬账。

## 十一、落地三步

| 步 | 做什么 | 验收 |
|---|---|---|
| 1 | 装包：`git clone` → `uv sync --extra server` → 权重（ModelScope，或 `HF_ENDPOINT=https://hf-mirror.com`）→ `start_server.bat` | `http://127.0.0.1:7860` 能开、`/health` 正常、能用她的录音试听一句 |
| 2 | bot 侧 Provider：`tools/local_tts_server.py` 增加 IndexTTS2 后端（`/api/v1/tts` SSE），`TTS_ENGINE=f5|indextts2` 切换 | 同一条短句，两个引擎都能出声 |
| 3 | 情绪映射：`memory/hormones_state.json` / mood → `emo_vector`(8 轴) + `emo_alpha`；音色用预设 | 同一句话在"开心/生气/难过"状态下音色不变、语气变化 |
