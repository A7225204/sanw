# video-watch-plus 对比分析报告（vs 大肥鱼的「看视频」）

## 一、一句话结论

**值得吸收三处，不值得整包替换。**

它是**给 agent 用的技能包**（ffmpeg 量测 + 规程文档），强在「先量测再决定看哪一帧」和「原始分辨率读小字」；
你现在这套是**端到端管线**（下载 → 宫格 → 识图 → 转写 → 缓存 → 评论/学习），强在闭环。
直接对调，等于拿掉你的手和脚换一副更好的眼睛。

---

## 二、它到底是什么（拆解）

不是模型，不是插件，是**一套流程 + 命令行工具**，靠 `SKILL.md` 约束 agent 的执行顺序：

| 阶段 | 命令 | 花 token 吗 | 产出 |
|---|---|---|---|
| 量测全片 | `vw.py probe` | **不花**（纯 ffmpeg） | 切点 / 冻结段 / 静音事件 / 运动曲线 → `timeline.json` |
| 算采样点 | `vw.py plan` | **不花** | 骨架 16 帧 + 事件组 3 帧，**明确打印最大盲区** |
| 拼图版 | `vw.py sheet` | 不花 | 3×3 图版 + `manifest.json`（第几行第几列 = 第几秒） |
| 读小字 | `vw.py read --region x,y,w,h` | 花（裁出来的面板） | 原始分辨率裁切放大后的图 |
| 听声音 | `scripts/audio_probe.py` | **不花**（numpy 算量） | 判型：静音 / 纯音 / 音乐 / 未达判据（**故意没有"语音"这一档**） |
| 转写 + 验伪 | `scripts/asr_hallucination_check.py` | 花（本地 whisper） | 文本 + 可信/幻觉判定 |

核心思想一句话：**ffmpeg 负责「什么时候」，眼睛负责「是什么」，耳朵负责「说了什么」**，
三路冲突时按 `SKILL.md` 的硬规则裁决（时间只信 manifest、文字以画面为准、音频冲突标「不确定」）。

## 三、你现有的看视频（拆解）

`media_fetch.fetch(url)`：B站走 `yt-dlp`、抖音走浏览器截 `aweme/detail` 接口 → 落到 `data/media_cache/<平台>/<id>.mp4`，
分析结果存同名 `.txt`，下次同链接直接读缓存。

- **抽帧**：`storyboard.scan_cuts()` 找切点 → `alloc_cells()` 分格 → `compose_sheet()` 拼 9 宫格（每张 9 格 + 时间码），
  长片按 `window=300s` 切多张；片子越长越只挑几张识图。
- **识图**：把宫格图丢给视觉通道（谷歌/硅基/火山/本地）。
- **转写**：`asr._transcribe_wav()` → 硅基流动 SenseVoiceSmall，**一路转写、无对照**，结果截 400 字。
- **回退**：分镜失败就抽 3 帧识图。

## 五、它真正值得抄的三点

### 1. 先把「漏了什么」量化出来

`plan` 会打印 `最终最大盲区 1.26s`——这句话的意思是「两帧之间最多有 1.26 秒是没人看过的」。
你现在的宫格**只告诉你看了哪几秒，不告诉你没看哪几秒**，长视频尤其致命（README 自己算过：2 小时素材骨架仍是 16 帧 ≈ **7.5 分钟才看一眼**）。

> 抄法：`storyboard.sheet_text()` 末尾加一行「最大盲区 X 秒」，纯计算，不装任何东西。

### 2. 读小字必须裁到原始分辨率

它给的例子很实在：720×720 的视频，字幕条是 `--region 40,600,640,80`，裁下来放大再读。
你的宫格把整帧缩成 1/3 格子，一行 24px 的字缩完只剩 8px——识图模型当然读不出。

> 抄法：给 `media_fetch` 加一个「可疑区域裁切」步骤（ffmpeg `crop` + `scale`），
> 需要哪些区域由宫格图先粗定位，或让模型指个大概再裁。

### 3. ASR 会编台词，而你现在没有防线

它实测抓到的两种幻觉：纯 BGM 上转出 `字幕by索兰娅`，三个互不重叠的时间窗输出**完全同一句**。
判据是「VAD 无输出 + 强制模式文本重复 / `no_speech` ≥ 0.4」。

你现在的 `asr._transcribe_wav()` 是**一路 SenseVoice 直接取文本**，非空就当口播写进缓存和档案——
碰到纯 BGM 视频，等于让一句假台词进她的记忆。这是**现在就存在的风险**，不需要等新工具。

> 抄法（不换 ASR）：加一道守卫——空文本、超短文本、重复片段占比过高的转写标「不可信」，
> 不写入口播，只在日志里留一条。纯 Python，半天。

## 六、它的短板与风险

1. **不下载视频**：链接给它是没用的，得先有本地文件——你的 B站/抖音链路上它完全使不上力。
2. **没有缓存、没有 QQ、没有学习闭环**：整包接进来只是多一层 CLI，外面那圈还得你自己写。
3. **依赖重**：ImageMagick 7、faster-whisper、`av<19`（`av>=19` 会直接 `TypeError`）；本机三样都没装。
   ASR 虽然不上云，但纯 CPU 跑 `small`，长视频要等。
4. **Windows 是打过补丁的**：上游 `drawtext` 吃不下盘符路径（`fontfile=C:/x.ttf` 失败），它自己补的——
   说明上游在 Windows 上本来就脆。
5. **`audio_probe` 会误判**：78 秒有人声的短片被判成「纯音/提示音」。它自己承认只能当**候选**，
   最终「有没有人说话」还得看 ASR 的 VAD。
6. **长视频没实测**：README 明说「⚠️ 长素材本身还没实测过」。
7. **仓库很新**：18★、5 天前最后一次提交、单人维护，文档比代码还重（README 29KB + SKILL.md 11KB）。

## 七、怎么用（三档，按性价比排）

**A 档｜只抄思路（0 依赖，建议先做）**
- `storyboard` 输出「最大盲区」；
- ASR 加可信度守卫（重复率/空文本/超短）；
- 媒体分析文本里注明「本片采样 n 帧，最大盲区 x 秒」。
- 工作量 ≈ 1 天，风险几乎为零。

**B 档｜借它的量测与裁切（推荐）**
- 把 `probe`/`plan` 的采样逻辑移植进 `storyboard.scan_cuts/alloc_cells`（或直接调 `vendor/vw.py`）；
- 装 ImageMagick，启用 `--region` 裁切读字幕/界面小字；
- 保留现有下载、缓存、评论链路不动。
- 工作量 ≈ 2~3 天（含装依赖、调阈值）。

**C 档｜整包接入（不推荐）**
- 它没有下载/缓存/QQ，等于在现有管线上再包一层 CLI；
- 依赖翻倍，还得为它维护一套 Windows 补丁。

---

## 八、结论

- 它的**方法论**（量测先行、盲区上界、原始分辨率读字、音频双路证伪）比你现在的单路管线更严谨，**这三条值得抄**。
- 它的**产品形态**（给 agent 的 CLI 技能）和你的**机器人管线**不是一回事：没有下载、没有缓存、没有 QQ 入口。
- 现在最该做的是 **A 档**：给 ASR 加可信度守卫 + 给分镜加盲区指标——这两件事不装新依赖，今天就能落地，
  而且直接修掉一个**已经在跑的风险**（假台词写进记忆）。
