# 缓存改造说明（2026-10-28，t3）

> 对应设计：`docs/缓存优化-方案对比.md`（推荐方案 A + B1 + D 诊断）。
> 对应审计：`docs/缓存审计-2026-10-28.md`。
> 本次只改 prompt 拼装的**换文本时机**与**块顺序**，人设文本、四个慢块的**内容**、
> 记忆写入、QQ/飞书双通道行为全部不变。

## 0. 一句话结论

- 慢块从"600 秒到期就重建"改成"**内容哈希不变就永不换文本；变了先积压，只在会话空闲 ≥600s 或积压 >1800s 时发布**"。
- 块顺序改成"**变更频率升序**"（低频在前、高频在后），私聊 `human→learn→archive`，群聊 `human→learn→archive→lexicon`。
- 补了整套诊断日志（`scope/channel/slow_fp/pub_fp/snap_hit/snap_age/pend/pub/prefix_tok/hist_len/pid`）+ `token_meter` 的 `channel/gid` 两列。
- 私聊历史预算 9000→12000（设计 §6.4 的调参步，为了稳态命中站上 97%）。

真实 DeepSeek 对照（8 轮、每轮故意改慢块内容）：

| 场景 | 第 1 轮 | 第 2~8 轮 | 加权 |
|---|---:|---:|---:|
| **改后**（hash，内容变了只积压） | 21.4%（冷） | **95.1~96.3%** | 86.57% |
| 改前等价（`PROMPT_SLOW_MODE=off`，每轮把新内容拼进前缀） | 97.4%（沿用上轮缓存） | **21.9~23.0%** | 31.53% |

改前等价场景的断点**固定落在 2048/2176 token**，与审计里那条 10.5K 会话"每轮断在 2176"完全同源。

**生产复测（2026-10-28 12:40–12:58，双通道 42 轮）**：飞书 23 轮 **96.79%**（P=14,156，上限 96.80%）、

## 2. 阶段一：只加日志（先诊断，不动结构）

### 2.1 新增字段

每轮聊天在 `build_prompt_parts` 末尾打一行（nonebot logger → `logs/bot_restart.out.log`）：

```
[缓存] 块指纹 scope=private_100000000 channel=qq private=1 mode=hash
  lexicon=da39a3ee human=45df7e56 archive=e2dd25fa learn=755cbf65
  slow_fp=f9142942 pub_fp=f9142942 snap_hit=0 snap_age=0 pend=0 pub=1
  pub_reason=cold tail=0 hist_len=-1 hist_tok=-1 prefix_tok=3881 pid=26272
```

| 字段 | 含义 | 怎么用 |
|---|---|---|
| `scope` | 会话身份（`private_<uid>` / `<群号>`） | QQ 私聊与飞书私聊**同 scope**（都是 `private_<uid>`） |
| `channel` | `qq` / `feishu` | 同 scope 两条通道交替出现 → 才可能是"双通道各拼一份"（方案 D 的 D1） |
| `slow_fp` | 四个慢块**现拼内容**的 sha1 前 8 位 | 这一轮慢块内容到底变没变 |
| `pub_fp` | **已发布**文本的指纹 | `slow_fp != pub_fp` 且 `pend=1` = 有变更被延迟（新逻辑在正常工作） |
| `snap_hit` | 1=沿用上次已发布文本（前缀没动） | 连续 `snap_hit=1` 说明前缀稳定；`snap_hit=0` 的那次就是断点 |
| `snap_age` | 距上次发布多少秒 | 用来验证"不再有纯 TTL 触发的重建"（可以 >600s 而 `snap_hit` 仍为 1） |
| `pend` / `pub` / `pub_reason` | 积压中 / 发布次数 / 发布原因（cold·idle·stale·ttl·off） | 每 scope 每小时发布次数 = 验收指标（≤2 次/小时） |
| `hist_len` / `hist_tok` | 历史条数 / 估算 token | 判断断点是不是"历史压缩/回填"造成 |
| `prefix_tok` | 稳定前缀 + 历史的估算 token（≈ 本次 prompt 的可缓存部分） | 直接和 usage 里的 `prompt_tokens/cached_tokens` 对账 |
| `pid` | 进程号 | 交替出现两个 pid = 双进程（D1 的确证） |

## 3. 阶段二：结构改造

### 3.1 改造后的消息布局

```
[system] 安全指令 + 人格卡 + 桌宠设定 + 私聊/隐私规则 + 规则 + 活人感 + 状态读法
        + 【慢块（新顺序）】                       ← 前缀，内容不变就一直命中
[user/assistant…] 历史真实多轮（只增不改）
[system] 回忆 / 群聊近况（按需）
[system] 易变尾巴（今日状态/对象/情绪/关系/别复读）
[user] 最新一句
```

慢块顺序（`_slow_layout`）：

| 场景 | 改前 | 改后（默认 `PROMPT_SLOW_ORDER=churn`） |
|---|---|---|
| 私聊 | lexicon → human → archive → learn | **human → learn → archive** |
| 群聊 | lexicon → human → archive → learn | **human → learn → archive → lexicon** |

依据 t1 的实测变更频率：human 6 天 1 次、learn 每天 1~2 次、archive 活跃时分钟级、群 lexicon 一天几十次。
"某块变了"只打掉它**后面**的块，所以高频块放最后。私聊一次 archive 变更可少打掉 learn（≈580 tok）。

### 3.2 慢块状态机（方案 A）

```python
_SLOW_STATE[(gid, is_private)] = {text, fp, published_at, last_call, pending, publishes}

fp == 已发布 fp            → 沿用旧文本，清 pending（★ 不再有"到期就重建"）
fp != 已发布 fp            → pending=(最新 fp, 最新文本, 积压起点)
     idle  (now-last_call > 600s)  → 发布（原因 idle：用户回来第一条，本来就要吃冷启动）
     stale (now-积压起点 > 1800s)  → 发布（原因 stale：记忆最多陈旧 30 分钟）
     否则                          → 继续用旧文本，前缀不动
冷启动（第一次见这个 scope） → 直接发布（原因 cold）
```

关键点：

1. **纯 TTL 重建被删除**：`snap_age` 可以无限增长，只要内容不变就永不换文本（审计 P4 的"到期 7 次、7 次全断"不会再发生）。
2. **发布时机只挑"本来就要断"的地方**：空闲 ≥600s 后用户回来第一条，服务端缓存本来就大概率过期，此时发布不额外加价。
3. **有上限兜底**：积压最多 1800s，保证 `archive`/`lexicon` 最多陈旧半小时（人设与长期事实不受影响，它们不在慢块里）。
4. **键用 `str(gid)`**：QQ 私聊与飞书私聊都是 `private_<uid>`，**同进程内两条通道天然共享一份已发布文本**（不需要额外做 D2 就能避免"两条通道各自发布互相打脸"）。
5. 状态表 >200 条时按 `last_call` 淘汰最旧 100 个（不会误删活跃会话）。

### 3.3 环境变量（全部可单独调 / 关）

| 变量 | 默认 | 作用 |
|---|---|---|
| `PROMPT_SLOW_MODE` | `hash` | `hash`=新逻辑；`ttl`=回到 10-27 的纯 TTL；`off`=每轮现拼（诊断用） |
| `PROMPT_SLOW_PUBLISH_GAP` | `600` | 空闲多久算"自然断点"（可发布） |
| `PROMPT_SLOW_MAX_STALE` | `1800` | 积压上限（秒），越大越省命中率、记忆越陈旧 |
| `PROMPT_SLOW_ORDER` | `churn` | `legacy`=回到旧的 lexicon→human→archive→learn |
| `PROMPT_SLOW_TAIL` | 空 | 逃生舱（方案 C-single）：`archive`=把 archive 移出前缀挂到历史之后 |
| `HISTORY_TOKEN_BUDGET_PRIVATE` | `12000` | 私聊可缓存历史预算（本次 9000→12000） |
| `HISTORY_TOKEN_BUDGET_GROUP` | `7000` | 群聊历史预算（未动） |

### 3.4 回滚

**① 只回退逻辑（推荐，改完 `.env` 必须重启进程才生效）**：

```ini

PROMPT_SLOW_MODE=ttl          # 回到 10-27 的纯 TTL 快照
# PROMPT_SLOW_ORDER=legacy    # 可选：回到旧块序 lexicon→human→archive→learn
# HISTORY_TOKEN_BUDGET_PRIVATE=9000   # 可选：历史预算回退
```

**② 彻底回退代码（PowerShell 可直接执行；改完同样要重启进程）**：

```powershell
cd D:\qq-ai-bot
Copy-Item plugins\ai_group.py.bak_hashsnap_20261028 plugins\ai_group.py -Force   # 回到 t3 阶段一（有日志、旧 TTL 快照）
Copy-Item plugins\ai_group.py.bak_prehash_20261028  plugins\ai_group.py -Force   # 回到改造前（无日志、无状态机）
.\.venv\Scripts\python.exe -m py_compile plugins\ai_group.py                     # 先自检再重启
```

> 旧写法 `copy /Y …` 是 cmd 语法，在 PowerShell 里会报 `A positional parameter cannot be found`，已改掉（t6/F2）。
> 若必须在 cmd 里跑，用 `copy /Y src dst` 并加 `cmd /c` 前缀。

**③ 回滚后必须一起做的两件事**：

1. **重启 bot**——`.env` 和 `ai_group.py` 都是进程启动时读入的，不重启等于没改
   （重启会带来一次冷启动断点，属预期）；
2. **清理 `.env` 里本改造新增的变量**——`PROMPT_SLOW_MODE` / `PROMPT_SLOW_PUBLISH_GAP` /
   `PROMPT_SLOW_MAX_STALE` / `PROMPT_SLOW_ORDER` / `PROMPT_SLOW_TAIL`（以及回退时临时写的
   `HISTORY_TOKEN_BUDGET_PRIVATE`），否则下次改回来时会静默沿用旧值。

`token_meter.py` 的两列是纯追加，不影响旧代码读取，可不回滚。

### 5.1 为什么"97%"这条要单独算清楚

稳态命中 = **1 − T/P**（T = 易变尾巴 + 最新一句 + 上一轮那一问一答，实测 ≈434~452 tok；P = 本次 prompt）。

| P（prompt） | 上限 | 说明 |
|---:|---:|---|
| 10.5K（改前真实值） | 95.9% | 即使慢块一次都不变，也到不了 97% |
| 13.7K / 14.2K（2026-10-28 复测，QQ/飞书） | 96.7% / 96.8% | 达标线上的实测档 |
| 15.1K / 14.5K（T/0.03） | 97.0% | 再涨 ~700~900 tok 历史（约 6~8 轮对话）即可越过 97% |
| 16K（历史预算 12000 撑满后） | 97.3% | 预算 12000 允许的上限 |

所以：

- 本次改造把**断点**问题解决了（改前同一会话 18.9~27.6% → 现在 96.4~96.8%，42 轮 0 断点）；
  97% 这最后一步是**分母**问题——历史还在长，P 从 13.7K/14.2K 涨到 15K 就自然越过 97%；
- 想立刻到 97% 只能做设计 §6.4 的 **tail↓（无损压缩尾巴 60~120 tok）**，那会动"状态/情绪/关系"措辞，
  队长已定为红线不做；本次没做。

### 8.1 分通道命中率 + 距 97% 缺口（口径 = 1−T/P）

把下面这段存成 `%TEMP%\cache_report.py` 再跑；也可以用 PowerShell 一次性生成：

```powershell
@'
# -*- coding: utf-8 -*-
"""缓存命中分通道报表（只读 DB，不写任何东西）。

用法：
    .venv\\Scripts\\python.exe <本文件>                 # 默认最近 60 分钟
    .venv\\Scripts\\python.exe <本文件> 120             # 最近 120 分钟
    .venv\\Scripts\\python.exe <本文件> 0 12:45         # 从今天 12:45 起（0=不用相对窗口）
    .venv\\Scripts\\python.exe <本文件> 0 12:45 1       # 最后一位=同时打印 memory_merge/utility

口径（队长第 2 次修订）：
    命中率    = Σcached / Σprompt
    稳态上限  = 1 − T/P，T 取"每次调用没命中的 token"的**中位数**（避开冷启动/断点这类长尾）
      · 平均 P ≥ 14500 → 直接对 97% 判定
      · 平均 P <  14500 → 按上限判定（实测 ≥ 上限 ⇒ 除设计内的 T 外没有额外断点）
    距 97% 缺口 = (0.97 − 实测) × Σprompt        （正数=还差这么多 token 的命中）
    补到 97% 需要的平均 P ≥ T/0.03；差额就是还要长多少历史
"""
import os
import pathlib
import sqlite3
import statistics
import sys
from datetime import datetime, timedelta

DB = pathlib.Path(os.environ["APPDATA"]) / "dsh-pet-standalone-webm-chat" / "shared_memory.db"
TARGET, P_THRESHOLD = 0.97, 14500

window_min = int(sys.argv[1]) if len(sys.argv) > 1 else 60
since_hhmm = sys.argv[2] if len(sys.argv) > 2 else ""
also_non_chat = (len(sys.argv) > 3 and sys.argv[3] not in ("0", "", "false"))

if since_hhmm:
    since = f"{datetime.now():%Y-%m-%d} {since_hhmm}:00"
    label = f"从 {since} 起"
else:
    since = (datetime.now() - timedelta(minutes=window_min)).strftime("%Y-%m-%d %H:%M:%S")
    label = f"最近 {window_min} 分钟（{since} 起）"

conn = sqlite3.connect(f"file:{DB}?mode=ro", uri=True)
cols = [r[1] for r in conn.execute("PRAGMA table_info(token_usage)").fetchall()]
if "channel" not in cols or "gid" not in cols:
    print("!! token_usage 缺少 channel/gid 列")
    raise SystemExit(1)

scopes = ("chat",) if not also_non_chat else ("chat", "memory_merge", "utility", "vision")

print(f"== 窗口：{label} ==")
rows = conn.execute(
    "SELECT ts, coalesce(channel,''), coalesce(gid,''), scope, prompt_tokens, cached_tokens "
    "FROM token_usage WHERE ts >= ? ORDER BY ts",
    (since,),
).fetchall()
if not rows:
    print("窗口内没有数据（主人还没发消息 / 时间点写错了）。")
    raise SystemExit(0)

# ---- 明细 ----
print(f"\n== 每次调用（scope=chat 全列；其它 scope 只在汇总里）==")
print(f"{'ts':>19} {'channel':>8} {'gid':>22} {'prompt':>8} {'cached':>8} {'miss':>7} {'hit':>8}  标记")
by_ch = {}
for ts, ch, gid, scope, prompt, cached in rows:
    if scope != "chat":
        continue
    by_ch.setdefault(ch or "(未标注)", []).append(
        {"ts": ts, "gid": gid, "p": prompt or 0, "c": cached or 0})

def _t_struct(calls):
    """结构 T：先按最小值 3 倍剔掉冷启动/断点，再取剩下的中位数。"""
    misses = [c["p"] - c["c"] for c in calls]
    if not misses:
        return 0, misses
    floor = min(misses)
    keep = [m for m in misses if m <= 3 * max(floor, 1)]
    return (statistics.median(keep) if keep else floor), misses


for ch, calls in sorted(by_ch.items()):
    t_robust, _ = _t_struct(calls)
    for i, c in enumerate(calls):
        miss = c["p"] - c["c"]
        flag = ""
        if i == 0 and c["c"] < 0.5 * c["p"]:
            flag = "冷启动/首调"
        elif t_robust and miss > 2 * t_robust:
            flag = "断点（miss 突增）"
        print(f"{c['ts']:>19} {ch:>8} {c['gid']:>22} {c['p']:>8} {c['c']:>8} "
              f"{miss:>7} {100.0 * c['c'] / max(c['p'], 1):>7.2f}%  {flag}")

# ---- 分通道判定 ----
print("\n== 分通道判定（scope=chat）==")
all_ok = True
for ch, calls in sorted(by_ch.items()):
    n = len(calls)
    sp = sum(c["p"] for c in calls)
    sc = sum(c["c"] for c in calls)
    hit = sc / max(sp, 1)
    p_avg = sp / max(n, 1)
    p_med = statistics.median([c["p"] for c in calls])
    t_robust, misses = _t_struct(calls)
    # T = 剔掉冷启动/断点后的中位数：就是"易变尾巴 + 最新一句 + 上一轮问答"的结构成本
    cap = 1.0 - t_robust / max(p_med, 1)
    gap = (TARGET - hit) * sp
    p_need = t_robust / (1 - TARGET) if t_robust else 0
    breaks = sum(1 for m in misses if t_robust and m > 2 * t_robust)
    print(f"\n[{ch}] calls={n}  Σprompt={sp}  Σcached={sc}")
    print(f"  实测命中        = {hit:.2%}")
    print(f"  平均/中位 P     = {p_avg:,.0f} / {p_med:,.0f} tok")
    print(f"  T（每次没命中，剔除断点后中位）= {t_robust:,.0f} tok；断点调用 {breaks} 次")
    print(f"  稳态上限 1−T/P  = {cap:.2%}")
    print(f"  距 97% 缺口     = (0.97 − {hit:.4f}) × {sp} = {gap:+,.0f} tok"
          f"（正=还差，负=已超出）")
    if n < 3:
        print("  判定：样本不足（<3 轮），本次只报实测与缺口，不做上限判定")
        ok = True
    elif p_avg >= P_THRESHOLD:
        ok = hit >= TARGET
        print(f"  判定：平均 P {p_avg:,.0f} ≥ {P_THRESHOLD:,} → 直接对 97% 判定 → "
              f"{'达标' if ok else '未达标'}")
    else:
        ok = hit >= cap - 0.0005
        print(f"  判定：平均 P {p_avg:,.0f} < {P_THRESHOLD:,} → 按上限判定 → "
              f"{'达标（除设计内 T 外无额外断点）' if ok else '未达标（存在额外断点，查 [缓存] 块指纹 snap_hit=0 的行）'}")
        print(f"  要到 97% 需平均 P ≥ T/0.03 = {p_need:,.0f} tok，还差 "
              f"{(p_need - p_avg):,.0f} tok 历史（≈ {(p_need - p_avg) / 120:,.0f} 轮对话）")
    all_ok = all_ok and ok
    if n < 10:
        print(f"  ⚠ 只测了 {n} 轮（验收要求 ≥10 轮）")

# ---- 合计 ----
tot_p = sum(c["p"] for calls in by_ch.values() for c in calls)
tot_c = sum(c["c"] for calls in by_ch.values() for c in calls)
if tot_p:
    hit = tot_c / tot_p
    print(f"\n== chat 合计 == Σprompt={tot_p} Σcached={tot_c} 命中={hit:.2%} "
          f"距97%缺口=(0.97−{hit:.4f})×{tot_p}={((TARGET - hit) * tot_p):+,.0f} tok")
missing = [ch for ch in ("qq", "feishu") if ch not in by_ch]
if missing:
    print(f"  提示：缺通道 {missing} 的数据（飞书要在飞书里私聊机器人；QQ 与飞书同 scope，"
          f"但 channel 列会区分）")

if also_non_chat:
    print("\n== 其它 scope（不参与验收，仅供参考）==")
    agg = {}
    for ts, ch, gid, scope, p, c in rows:
        if scope == "chat":
            continue
        d = agg.setdefault(scope, [0, 0, 0])
        d[0] += 1
        d[1] += p or 0
        d[2] += c or 0
    for scope, (n, p, c) in sorted(agg.items()):
        print(f"  {scope:>14} calls={n:<4} prompt={p:<8} cached={c:<7} hit={100.0 * c / max(p, 1):.2f}%")
'@ | Set-Content -Encoding UTF8 $env:TEMP\cache_report.py
cd D:\qq-ai-bot
.venv\Scripts\python.exe $env:TEMP\cache_report.py 0 12:45      # 从今天 12:45 起（复测建议：用主人开始发消息的时间）
.venv\Scripts\python.exe $env:TEMP\cache_report.py 60           # 或：最近 60 分钟
.venv\Scripts\python.exe $env:TEMP\cache_report.py 0 12:45 1    # 末位 1 = 同时打印 memory_merge/utility
```

- `T（剔除断点后中位）` = 每次调用没命中的 token（易变尾巴 + 最新一句 + 上一轮问答）；
